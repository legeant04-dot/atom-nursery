### ⬜ ขั้น 4 — ผูกโดเมนกับ GitHub Pages
Settings → Pages → Custom domain → รอ DNS check ผ่าน → **เปิด "Enforce HTTPS"**
*(ใบรับรอง Let's Encrypt ฟรี ออกให้อัตโนมัติ อาจใช้เวลาถึง 24 ชม.)*

### 🔴 ขั้น 5 — **แก้ปลายทางที่ LINE** *(ลืมข้อนี้ = ทั้งโรงเรียนล็อกอินไม่ได้)*
LINE Developers → LIFF → **Endpoint URL** → โดเมนใหม่
LINE Login channel → **Callback URL** → เพิ่มโดเมนใหม่

> **อย่าลบของเดิมทิ้งทันที** — ใส่ทั้งสองอันไว้ก่อน จนกว่าจะแน่ใจว่าไม่มีใครค้างอยู่ที่เก่า

### 🔴 ขั้น 6 — แก้ที่ Google

## 🔙 แผนถอย

> ### 🔴 จุดที่ย้อนยากจริง ๆ ไม่ใช่สวิตช์ — คือตอนผูกโดเมนกับ GitHub Pages (ขั้น 4)
>
> **ทันทีที่ผูก** GitHub Pages จะ 301 ที่อยู่เดิม (`legeant04-dot.github.io/atom-nursery/`)
> ไปยังโดเมนใหม่ **โดยที่เรายังไม่ได้เปิดสวิตช์อะไรเลย** — นี่คือพฤติกรรมของ Pages เอง
> และคือเหตุผลทั้งหมดที่ตัวกันหน้าขาวในขั้น 1 ต้องมาก่อน
>
> *เอกสารฉบับก่อนเขียนว่าจุดวิกฤตคือขั้น 8 — ไม่ใช่ · ขั้น 8 คือกันชนชั้นที่สอง ไม่ใช่ชั้นแรก*

| ปัญหา | ถอยยังไง | ใช้เวลา |
|---|---|---|
| **DNS ยังไม่ขึ้น / ชี้ผิด** *(ก่อนขั้น 4)* | แก้ที่ผู้รับจด · ของเดิมยังทำงานปกติ **ยังไม่มีใครเดือดร้อน** | นาที–ชม. |
| **ใบรับรอง HTTPS ไม่ออกสักที** *(หลังขั้น 4)* | **ถอด Custom domain ออกจาก GitHub Pages Settings** → ที่อยู่เดิมกลับมาให้บริการทันที | ~1–5 นาที |
| **LIFF / Google ล็อกอินไม่ได้** | ใส่ URL เดิมกลับเข้าไป *(ของเดิมยังไม่ได้ลบ — ขั้น 5 สั่งไว้)* | ทันที |
| **โดเมนใหม่พังหลังเปิดสวิตช์แล้ว** | ① ถอด Custom domain ก่อน (ที่อยู่เดิมกลับมา) ② ปิดสวิตช์ `MIGRATE_TO=''` แล้วปล่อยรุ่นใหม่ | ~10 นาที |

**ทำไมข้อสุดท้ายถึงถอยได้ ทั้งที่ฉบับก่อนบอกว่าถอยไม่ได้:**
โดเมนทั้งสองชี้ไปที่ **GitHub Pages ตัวเดียวกัน จากรีโปเดียวกัน** — เครื่องที่ถูกส่งไปโดเมนใหม่แล้ว
ยังได้รับรุ่นใหม่ตามปกติ เพราะมันโหลดจากที่เดียวกัน · สิ่งที่ถอยไม่ได้จริง ๆ มีอย่างเดียวคือ
**กรณีที่โดเมนใหม่เข้าไม่ถึงเลย** (DNS ตาย) ซึ่งการถอด Custom domain แก้ได้ และนั่นคือสเต็ปแรกเสมอ

> ### 🔴 เรื่อง CNAME — กับดักที่พังเงียบในรุ่นถัดไป
>
> Pages ของเราปล่อยด้วย Actions และอัปโหลด **เฉพาะ `dist_pages/`** เป็น artifact
> ส่วน `tools/build_web.js` ขึ้นต้นด้วย `fs.rmSync(dist_pages)` — **ลบทิ้งทั้งโฟลเดอร์ทุกครั้งที่ build**
>
> ถ้าตั้ง Custom domain ผ่านหน้าเว็บ GitHub มันจะ commit `CNAME` ไว้ที่ **รากรีโป**
> ซึ่งไม่ได้ถูกอัปโหลดไปกับ artifact เลย · ทั้งสองทางให้ผลเดียวกัน:
> **โดเมนใช้ได้ในวันแรก แล้วหลุดเงียบ ๆ ตอนปล่อยรุ่นถัดไป** — พังตอนที่ไม่มีใครมองแล้ว
>
> ที่ถูกคือสร้างไฟล์ `webapp/CNAME` มีบรรทัดเดียวว่า `atomnurseryapp.com`
> `walk()` ใน build_web.js คัดลอกทุกไฟล์ใน `webapp/` ไปให้เอง
> **`tools/test_domain_move.js` ข้อ 7 จะแดงถ้า CNAME ไปโผล่ที่รากรีโป** *(ทดสอบแล้วว่าจับได้จริง)*

## ❓ คำถามที่ควรถามก่อนเริ่ม

**"ทำไมไม่ย้ายโฮสต์ไปด้วยเลยทีเดียว?"**

เพราะถ้าย้ายสองอย่างพร้อมกันแล้วพัง **เราจะไม่รู้ว่าพังเพราะอะไร** — และนี่คือระบบที่โรงเรียนใช้จริงทุกเช้า
*(และ ผอ. เลือก "ย้ายโดเมนก่อน แยกคนละรอบ" ไว้แล้วเมื่อ 22/10)*

**"ผู้ปกครองต้องติดตั้งแอปใหม่ไหม?"**

**ไม่ต้อง** — นั่นคือเหตุผลทั้งหมดของขั้น 1 และ 8
ของเดิมบนเครื่องเขาจะพาเขาไปที่ใหม่เอง · **และนี่คือเหตุผลที่การมีโดเมนของตัวเองคุ้ม**: ครั้งหน้าที่เราย้ายโฮสต์ ผู้ปกครองจะไม่รู้สึกอะไรเลยแม้แต่น้อย
