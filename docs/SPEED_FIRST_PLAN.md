**ที่ช้าไม่ใช่ที่เก็บข้อมูล** (วัด 07/10 · 14 คู่ตัวอย่างบนระบบจริง):

| ส่วนของ request ที่ p50 = 7.4s | เวลา | สัดส่วน |

> **ย้ายฐานข้อมูลอย่างเดียว = เร็วขึ้น 5.6%** · ต้องย้าย **ที่ request ไปลง** ถึงจะได้ 20–50 เท่า

## 🏗️ สถาปัตยกรรมปลายทาง

```
เบราว์เซอร์ ──เส้นเร็ว──→ โฮสต์ใหม่ (Node/Edge) ──→ Postgres   ← อ่าน + เขียนส่วนใหญ่
            └─เส้นเดิม──→ Apps Script ───────────→ Postgres   ← Drive · LINE push · trigger · SlipOK
```

**ทั้งสองทางอ่าน-เขียน Postgres ตัวเดียวกัน** — นี่คือข้อที่ห้ามพลาด

> 🔴 **ทำไมถึง "ห้ามให้เส้นหนึ่งอ่าน Postgres อีกเส้นเขียน Sheets"**
> `tools/pg_sync.js` เป็นการซิงก์ **ทางเดียว นอกเส้นทาง request** (ชีต → Postgres ตามรอบ)
> โดยตั้งใจ — เพราะการยิง Supabase ทุกครั้งที่เขียนคือความผิดพลาดเดียวกับที่เคยทำให้
> **20:00 fail 37%** ตอนที่มี LINE push อยู่ใน write lock
>
> แปลว่าถ้าแยกกันคนละที่เก็บ **ครูเช็คอินเด็กแล้วเปิดรายชื่อจะเห็นข้อมูลเก่า**
> — ต้องเป็น Postgres ที่เดียวทั้งสองเส้น และ Sheets ปลดระวาง

## ✅ ของที่ทำเสร็จแล้วจริง (ไม่ต้องทำซ้ำ)

| | หลักฐาน |
|---|---|
| เอนจินรันบน Postgres | `tools/pg_engine.js` · **101 ชุดทดสอบรันบน Postgres จริง** |
| เขียนแบบทีละแถว ไม่ทับทั้ง collection | `pg_engine` เก็บ snapshot แล้ว emit INSERT/UPDATE/DELETE เฉพาะที่เปลี่ยน |
| ตัวย้ายข้อมูล + รายงานเงิน | `pg_migrate.js` · `test_pg_load.js` |
| ตัวตรวจส่วนต่าง | `pg_diff_check.js` |
| RLS กันข้อมูลข้ามโรงเรียน | `pg_rls_spike.js` — เขียนตามรูปแบบ PostgREST จริง |
| สคีมา | `docs/schema/001_init.sql` |

**และข้อที่ทำให้งานนี้เล็กกว่าที่คิดมาก:**
session token เป็น **HMAC แบบไร้สถานะ** — `base64url({uid,role,linkedId,iat,exp}).base64url(HMAC)`
โฮสต์ใหม่ **ตรวจ token ได้เองด้วย secret เดียวกัน ~1ms ไม่ต้องแตะฐานข้อมูล**

> **ล็อกอินไม่ต้องย้าย** · LINE LIFF · Google · การออก token ยังอยู่ GAS ทั้งหมด
> `Auth.gs` 883 บรรทัดไม่ต้องพอร์ต — ต้องการแค่ `verifySession_` ไม่กี่บรรทัด

## 🚧 ของที่ยังไม่มี

| | ขนาด |
|---|---|
| **โฮสต์ HTTP ที่รัน `pg_engine`** | ยังไม่มีเลย — `webapp/api.js` ยังชี้ `script.google.com` |
| ชั้นข้อมูลของ GAS ให้ไปอ่าน Postgres แทนชีต | **14 ไฟล์** แตะชีตโดยตรง · คอขวดอยู่ที่ `Db.gs` (201 บรรทัด) |
| 131 route ที่ shadow เอนจินอยู่ | ดูตาราง §2.6 ข้างล่าง |

### 131 shadow route — เหตุผลที่มันมีอยู่ และอันไหนหายไปบน Postgres

| จำนวน | เหตุผล | บน Postgres |
|---|---|---|
| **112** | เขียนทีละแถวบนชีต (เอนจินเขียนทับทั้ง collection) | ✅ **เหตุผลหายไป** — pg_engine เขียนทีละแถวอยู่แล้ว |
| 108 | ต้องใช้บริการ Apps Script (lock · cache · trigger) | ⚠️ ส่วนใหญ่ยังอยู่ GAS |
| 87 | ต้องใช้ Drive | ⚠️ ยังอยู่ GAS จนกว่าจะย้าย storage |
| 37 | ยิงออกนอกระบบ / เขียนกระดิ่ง | ⚠️ ยังอยู่ GAS |
| 36 | เขียนบันทึกตรวจสอบ PDPA | ⚠️ |
| **17** | ไม่มีเหตุผลเชิงกลไกเลย — อ่านล้วน | ✅ ย้ายได้ทันที |

*(ตัวเลขทับซ้อนกันได้ — route เดียวอยู่ได้หลายหมวด)*
