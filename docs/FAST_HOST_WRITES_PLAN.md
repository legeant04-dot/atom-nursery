## ระยะ W0 · รากฐาน (ยังไม่ย้าย route ไหน)

สิ่งที่ `server/routes.js` ต้องทำได้เพิ่ม — แต่ละข้อ **ประกาศต่อ route** แบบเดียวกับ `writes` วันนี้ ไม่ประกาศ = ล้มทันที:

1. **เพิ่มแถว (`appendObject_`)** — `appends: ['SHEET']` · แถวใหม่ลงตารางในธุรกรรมเดียวกับคำตอบ ·
   รหัสใหม่ (เช่น `genLeaveId_`) สร้างจากแถวที่โหลดมา **ภายใต้ล็อกเขียนของโรงเรียน** (advisory lock ตัวเดียวกับ Apps Script) จึงไม่ชนกัน
2. **ลบแถว (`deleteRow`)** — `deletes: ['SHEET']` · ลบตามรหัสแถว ไม่ใช่ตามลำดับ (ลำดับเลื่อนเมื่อลบ)
3. **ตั้งค่าโรงเรียน (`setConfigValue_`)** — upsert SCHOOL_CONFIG + bump cache version ของ config
4. **บันทึกตรวจสอบ (`logAudit` / `logAuditHr`)** — เปิดให้ทุก route ที่เขียน · 🔴 `AUDIT_LOG` มีชื่อซ้ำในสองสมุดงาน
   (MAIN → `audit_log` · HR → `hr_audit_log`) — sandbox วันนี้ไม่สนใจว่าเป็นสมุดงานไหน **ต้องแก้ก่อน** ไม่งั้น log ของ HR ไปผิดตาราง
5. **กระดิ่ง (`inboxAdd_`)** — คือการเพิ่มแถว ADMIN_INBOX ธรรมดา (ข้อ 1)
6. **รูปภาพ** — ยังปฏิเสธเหมือนวันนี้ (payload ที่มี `data:image` → ส่งต่อไป Apps Script)
7. **ชุดทดสอบกลาง "สถานะหลังเขียน"** — รัน route เดียวกันบน Apps Script (harness) และบนโฮสต์ (staging) จากข้อมูลเดียวกัน
   แล้วเทียบ **ทุกแถวของทุกชีตที่ประกาศ** ไม่ใช่แค่คำตอบ · ใช้ซ้ำได้ทุก route · ตรวจด้วยว่าชีตที่ไม่ได้ประกาศไม่เปลี่ยนเลย

## ระยะ W1 · route เล็ก ไม่มีเงิน ไม่มี LINE (พิสูจน์ว่ารากฐานใช้ได้)

holidays (add/edit/remove) · departments (add/remove/rename) · announcements (add/edit/delete) · Big Cleaning (add/remove) ·
ข้อความใบประกาศ · ข้อมูลบนใบเสร็จ · โควตาวันลา · เกณฑ์ DSPM · `unlockJournal` · `recallJournalsMany` (กระดิ่งอย่างเดียว) ·
`editLeave` · `cancelLeave` · `editStudentLeave`

ส่วนใหญ่เป็นหน้าจอแอดมินที่ใช้ไม่บ่อย — **ไม่ได้ทำให้เร็วขึ้นมาก แต่เป็นที่ทดสอบรากฐานที่ความเสี่ยงต่ำที่สุด**

## ระยะ W2 · ส่ง LINE — ต้องตัดสินใจก่อน

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **ก. คิวส่ง LINE (outbox)** — โฮสต์บันทึกข้อความลงตาราง · Apps Script ส่งทุก 1 นาที | token LINE อยู่ที่เดิมที่เดียว · ไม่ต้องย้ายความลับ | ข้อความถึงช้าสูงสุด ~1 นาที · สลับระบบแล้วยังพึ่ง Apps Script |
| **ข. Cloud Run ส่งเอง** — token LINE อยู่ใน Secret Manager | ทันที · ไม่พึ่ง Apps Script | ความลับอยู่สองที่ · ต้องคุมโควตา 300 ข้อความ/เดือน ร่วมกันสองระบบ |

route ที่ได้ประโยชน์: แจ้งลาเด็ก (`studentAbsence`) · ความเห็นผู้ปกครอง/ครูตอบ · แจ้งเหตุบาดเจ็บ · ลาของเด็กโดยครู

## ระยะ W3 · งานประจำวันที่ใกล้เงิน

ลงเวลาครู (`staffCheckin`/`staffCheckout`) · ผู้ปกครองเช็คอิน · ครูเช็คอินแทน · ยื่น/อนุมัติใบลา ·
มี geofence · OT · เบี้ยขยัน — พิสูจน์แบบเดียวกับ `test_fast_host_money_live` ทุกบาท

## ระยะ W4 · เงินโดยตรง

บิล · สลิป · ชำระล่วงหน้า · เงินเดือน · OT จ่าย — **ผอ. ตรวจก่อนเปิดทีละกลุ่ม** · "เรื่องเงินเป็นเรื่องละเอียดและสำคัญมาก"

## อยู่ Apps Script ต่อ (ไม่ย้าย)

อัปโหลดรูป/ไฟล์ไป Drive (สลิป · QR · ภาพใบประกาศ) · SlipOK · การแลก token LINE/Google · กู้คืนข้อมูล/สำรอง ·
เครื่องมือวินิจฉัย Apps Script · ตัวส่งออกที่ห้ามมี route (ดู `atom-two-exporters`)

## กติกาที่ใช้ทุกระยะ

- route หนึ่งย้ายได้เมื่อ **สถานะหลังเขียนเท่ากับ Apps Script ทุกแถว** บน staging · ทุกบทพิสูจน์อยู่ในชุดทดสอบถาวร
- ประกาศชีต/คอลัมน์ที่เขียนได้ต่อ route · เขียนนอกที่ประกาศ = ล้มทั้งคำขอ ไม่บันทึกอะไรเลย
- ล็อกเดียวกับ Apps Script · ธุรกรรมเดียว · ล้มกลางทาง = ไม่มีอะไรถูกบันทึก
- ไม่มีข้อมูลจริงบน staging จนกว่า PDPA จะลงนาม
