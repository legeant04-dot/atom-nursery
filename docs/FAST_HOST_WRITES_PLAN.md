## ระยะ W0 · รากฐาน (ยังไม่ย้าย route ไหน)

สิ่งที่ `server/routes.js` ต้องทำได้เพิ่ม — แต่ละข้อ **ประกาศต่อ route** แบบเดียวกับ `writes` วันนี้ ไม่ประกาศ = ล้มทันที:

1. **เพิ่มแถว (`appendObject_`)** — `appends: ['SHEET']` · แถวใหม่ลงตารางในธุรกรรมเดียวกับคำตอบ ·
   รหัสใหม่ (เช่น `genLeaveId_`) สร้างจากแถวที่โหลดมา **ภายใต้ล็อกเขียนของโรงเรียน** (advisory lock ตัวเดียวกับ Apps Script) จึงไม่ชนกัน
2. **ลบแถว (`deleteRow`)** — `deletes: ['SHEET']` · ลบตามรหัสแถว ไม่ใช่ตามลำดับ (ลำดับเลื่อนเมื่อลบ)
3. **ตั้งค่าโรงเรียน (`setConfigValue_`)** — upsert SCHOOL_CONFIG + bump cache version ของ config
4. **บันทึกตรวจสอบ (`logAudit` / `logAuditHr`)** — เปิดให้ทุก route ที่เขียน · 🔴 `AUDIT_LOG` มีชื่อซ้ำในสองสมุดงาน
   (MAIN → `audit_log` · HR → `hr_audit_log`) — sandbox วันนี้ไม่สนใจว่าเป็นสมุดงานไหน **ต้องแก้ก่อน** ไม่งั้น log ของ HR ไปผิดตาราง
5. **กระดิ่ง (`inboxAdd_`)** — คือการเพิ่มแถว ADMIN_INBOX ธรรมดา (ข้อ 1)
6. **รูปภาพ** — ยังปฏิเสธเหมือนวันนี้ (payload ที่มี `data:image` → ส่งต่อไป Apps Script)
7. **ชุดทดสอบกลาง "สถานะหลังเขียน"** — รัน route เดียวกันบน Apps Script (harness) และบนโฮสต์ (staging) จากข้อมูลเดียวกัน
   แล้วเทียบ **ทุกแถวของทุกชีตที่ประกาศ** ไม่ใช่แค่คำตอบ · ใช้ซ้ำได้ทุก route · ตรวจด้วยว่าชีตที่ไม่ได้ประกาศไม่เปลี่ยนเลย

## ระยะ W2 · ส่ง LINE — ✅ ผอ. เลือก "ข. Cloud Run ส่งเอง" และอนุมัติแผน (2026-11-09)

> ทางที่ไม่ได้เลือก: ก. outbox ให้ Apps Script ส่งทุก 1 นาที — ตกไปเพราะเป้าหมายปลายทางคือเลิกใช้ Apps Script

### หลักคิด: ใช้ "ท่อเดียว" ที่มีอยู่แล้ว

การส่ง LINE ทุกครั้งในระบบ (22 จุด ใน 8 ไฟล์) วิ่งผ่าน **`linePush_` ใน `src/Line.gs` ฟังก์ชันเดียว** ·
และมีคิวอยู่แล้ว (`LINE_DEFER_`) — ระหว่างถือล็อกเขียน ข้อความถูก "จดไว้" แล้วส่งหลังปล่อยล็อก ·
W2 ใช้แบบเดียวกันทุกประการ ไม่แก้ handler ตัวไหนเลย:

1. **ใน sandbox (`server/routes.js`)** — `linePush_` ถูกแทนด้วยตัวจด: บันทึก `{to, messages}` ตามลำดับ ไม่ยิงอะไรออกไป ·
   ทุกอย่างก่อนหน้า (สวิตช์ 15 หัวข้อ `notifyChannels_` · หาผู้รับ `lineRecipientsFor_` · โหมดสาธิตไม่ส่ง · เหตุฉุกเฉินส่งเสมอ)
   เป็นโค้ดของ Apps Script ตัวเดิม → **ส่งหาใคร ส่งเรื่องอะไร ตัดสินแบบเดียวกันทุกตัวอักษร**
2. **โฮสต์ (`server/host.js`)** — บันทึกข้อมูลลง Postgres (commit) **ก่อน** แล้วจึงส่ง LINE ·
   ถ้าการบันทึกล้ม = ไม่ส่งอะไรเลย (เหมือนวันนี้: ไม่แจ้งเรื่องที่ไม่ได้เกิด)
3. **ส่งไม่สำเร็จไม่ทำให้คำขอล้ม** — ข้อมูลบันทึกแล้ว · เหมือน `lineDeferFlush_` วันนี้ทุกอย่าง

| **คำตอบ "ส่งแล้วกี่คน"** | บาง handler นับ `if (linePushText_(…)) sent++` · ตัวจดตอบ true เมื่อมีผู้รับและโรงเรียนมี token — เหมือนคิวของ Apps Script วันนี้ (คำสัญญา ไม่ใช่ใบเสร็จ) |
| **บันทึกการส่ง** | log ของ Cloud Run: ผู้รับ (ตัดเหลือ 6 ตัวท้าย) · ผล · รหัส HTTP · **ไม่เก็บเนื้อความ** (PDPA) |

### 🔐 token ของ LINE

- **เก็บใน Secret Manager** ชื่อ `line-token-<รหัสโรงเรียน>` — หนึ่งโรงเรียนหนึ่ง OA หนึ่ง secret (พร้อมสำหรับหลายโรงเรียน) ·
  sandbox **ไม่เห็น token เลย** (handler ไม่ต้องรู้ · โค้ดที่เผลอ log ค่า config ก็ไม่มีอะไรรั่ว)
- **ช่วงเปลี่ยนผ่านอยู่สองที่:** Secret Manager (Cloud Run) + `school_config` (Apps Script อ่านหลังสลับระบบ) ·
  เมื่อ Apps Script เลิกส่ง LINE แล้ว → ลบออกจาก `school_config` เหลือที่เดียว
- 🔴 **ใส่ token จริงเมื่อวันสลับระบบเท่านั้น** — ผอ./ผู้ดูแลใส่เองใน Secret Manager (ผมไม่แตะค่าจริง) · และควร **ออก token ใหม่** ตอนนั้น (รายการหมุนความลับที่ค้างอยู่)

### 🧪 staging ห้ามส่งถึงใครจริง

- ตัวแปร `LINE_SEND` บน Cloud Run: **`capture`** (ค่าเริ่มต้น · จดแต่ไม่ส่ง) · `on` เฉพาะ production วันสลับระบบ
- staging ไม่มี secret token → ต่อให้ตั้งผิดก็ส่งไม่ได้ (สองชั้น)
