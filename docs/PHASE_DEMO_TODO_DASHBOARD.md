# ร่างแผน · Demo / สิ่งที่ต้องทำวันนี้ / สรุปภาพรวม (Admin เท่านั้น)

> ร่างเมื่อ **2026-10-21** ตามคำสั่ง ผอ. · ที่มา: วิเคราะห์ CoraClass (ระบบโรงเรียนสอนพิเศษ)
> **ยังไม่ได้เริ่มทำ — เป็นร่างให้ ผอ. เลือกลำดับและอนุมัติก่อน**

---

## ลำดับที่ผมแนะนำ — และเหตุผล

```
B · สิ่งที่ต้องทำวันนี้   →   C · สรุปภาพรวม   →   A · Demo Mode
   ได้ประโยชน์ทุกวัน           ใช้ข้อมูลชุดเดียวกับ B      ต้องรอ PDPA + แก้เรื่องล็อกอินก่อน
   ถูกที่สุด                                                 ขายไม่ได้จนกว่า PDPA จะเสร็จอยู่ดี
```

**ทำไม B ก่อน** — ข้อมูลทุกตัวที่ B ต้องใช้ **มีอยู่ในระบบครบแล้ว** สิ่งที่ขาดคือ "เรียงมันเป็นงานที่ต้องทำ"
เป็นงานที่ได้ผลเร็วที่สุดต่อแรงที่ลง และ ผอ. ได้ใช้ทุกเช้าตั้งแต่วันแรก

**ทำไม A ท้ายสุด** — Demo คืออาวุธการขาย แต่**ขายไม่ได้จนกว่า PDPA จะลงนาม** และ Demo ยังชนกับ
เรื่องที่ยังไม่มีคำตอบ: ระบบเราล็อกอินด้วย LINE อย่างเดียว — **คนที่ยังไม่ใช่ลูกค้า จะเข้าดูยังไง**

# 🅑 Phase B · "สิ่งที่ต้องทำวันนี้"

**เป้าหมาย:** เปิดแอปตอนเช้าแล้วรู้ทันทีว่า *วันนี้ต้องทำอะไร* ไม่ใช่ *ตัวเลขสรุปของเมื่อวาน*

### สิ่งที่ระบบรู้อยู่แล้ว (ไม่ต้องคำนวณใหม่)

| รายการ | มาจาก | กดแล้วไปไหน |
|---|---|---|
| ใบลารออนุมัติ | `pendingLeaves` | หน้าอนุมัติลา |
| สลิปรอตรวจ | `pendingPayments` | หน้าตรวจสลิป |
| คำขอลงเวลารออนุมัติ | `pendingAdminTimeRequests` | หน้าอนุมัติเวลา |
| ครูที่ยังไม่ลงเวลาออก | `staffMissingCheckout` | หน้าแก้เวลา *(มีแล้วใน v458)* |
| สมุดบันทึกที่ยังไม่ส่ง | `journalStatus` | หน้าสมุดบันทึก |
| เด็กที่ใกล้ถึงวันสุดท้าย | `endingStudents` | ประวัตินักเรียน |
| 🚪 **ครอบครัวที่ใกล้หมดช่วงผ่อนผัน 30 วัน** | `parentLinkDetail` | รายชื่อผู้ปกครอง |
| ยอดค้างชำระเกินกำหนด | `financeSummary` | หน้าการเงิน |
| 🔔 แจ้งเตือนในกล่องที่ยังไม่อ่าน | `adminInbox` | กล่องข้อความ |

### 🔴 กฎที่ต้องยึด

1. **รายการที่เป็นศูนย์ ต้องไม่ขึ้นเลย**
   แบนเนอร์เขียวว่า "ไม่มีอะไรค้าง" ทุกวัน คือเสียงรบกวน — และเสียงรบกวนคือสิ่งที่ทำให้คนเลิกอ่านหน้าจอที่สำคัญจริง *(บทเรียนเดียวกับ `parentDueCard`)*
2. **ทุกบรรทัดต้องเป็นสิ่งที่ "ทำวันนี้ได้"**
   ไม่ใช่สถิติ · "ขาดเรียน 11 วันเดือนนี้" ไม่ใช่งาน · "มีเด็ก 3 คนขาดติดกัน 3 วัน — ติดตาม" คืองาน
3. **ตัวเลขต้องมาจากที่เดียวกับหน้าจอที่มันลิงก์ไป**
   ถ้าหน้าแรกบอก 12 แล้วกดเข้าไปเจอ 9 **ทั้งหน้าจะไม่ถูกเชื่ออีกเลย**
4. **ไม่เพิ่มรอบเรียกเซิร์ฟเวอร์**
   ต้องขี่ไปกับ batch เดิมของหน้าแรก — Apps Script รันทีละคำสั่ง รอบใหม่ = แอดมินรอนานขึ้นทุกเช้า

**ขนาดงานโดยประมาณ:** 1 route รวม (`adminTodo`) + การ์ดบนหน้าแรก + เทสต์ที่ยืนยันว่าตัวเลขตรงกับหน้าปลายทาง

# 🅒 Phase C · สรุปภาพรวม (Admin เท่านั้น)

**เป้าหมาย:** ภาพการเงินและการดำเนินงานในหน้าเดียว — แบบที่ CoraClass ทำแล้วอ่านง่ายจริง

| ส่วน | เนื้อหา |
|---|---|
| 💰 รายได้เดือนนี้ | ยอดรวม + **กราฟแท่งย้อนหลัง 3 เดือน** |
| 📊 สถานะการดำเนินงาน | % เช็คชื่อแล้ว · % สมุดบันทึกส่งแล้ว · % ครูลงเวลาครบ |
| 👥 ตัวเลขโรงเรียน | นักเรียน/พนักงาน/ห้องเรียน |
| 🎉 วันหยุดถัดไป | จากปฏิทินโรงเรียน |

### 🔴 กฎที่ต้องยึด

1. **เรื่องเงินบนหน้าแรก ต้องตรงกับหน้าการเงินทุกบาท**
   ถ้าคำนวณใหม่เองอีกชุด วันหนึ่งมันจะไม่ตรง และ**วันนั้นเราจะไม่รู้ว่าอันไหนถูก** — ใช้ `financeSummary` ตัวเดิม
2. **"รายได้" ต้องนิยามให้ชัดบนหน้าจอ** — เงินที่*รับแล้ว* หรือเงินที่*ออกบิลแล้ว* · สองอันนี้ไม่เท่ากัน และคนอ่านจะเดาเอง
3. **เงินเดือน ผอ. ยังไม่นับในรายจ่ายรวม** *(มติ ผอ. 2026-09-30)* — ต้องเขียนกำกับบนหน้าจอ ไม่ใช่ซ่อนไว้ในโค้ด
4. **Admin เท่านั้น** — ไม่ใช่ Observer *(Observer อ่านได้ทุกอย่างก็จริง แต่เรื่องรายได้รวมคือการตัดสินใจแยกต่างหากของโรงเรียน)*

# 🅐 Phase A · Demo Mode

**เป้าหมาย:** ให้เจ้าของเนอสเซอรี่กดดูระบบเองได้ ทันที ไม่ต้องคุยกับเรา และไม่ต้องกลัวพังอะไร

> จากรายงานเทียบ 19 แพลตฟอร์ม (ก.ย. 2026): Brightwheel · Procare · Lillio · Playground · Illumine · LineLeader — **ไม่มีใครบอกราคา ต้องจองเดโมคุยกับเซลส์ทั้งหมด**
> **Demo ที่กดดูเองได้ + ราคาที่ติดไว้ = เราเป็นเจ้าเดียวในตลาด**

### 🔴 สามเรื่องที่ต้องตัดสินใจก่อนเขียนโค้ดบรรทัดแรก

**① ข้อมูลสาธิตต้องอยู่คนละสมุดงาน ไม่ใช่ "ธง" บนของจริง**

> ถ้า Demo เป็นแค่คอลัมน์ `IsDemo` บนชีตเดียวกับข้อมูลจริง **วันหนึ่งจะมี query ที่ลืมกรองมัน**
> และวันนั้นจะเป็นได้ทั้งสองทาง: เด็กสมมติโผล่ในรายงานจริง หรือ**เด็กจริงโผล่ในหน้าจอที่คนนอกกำลังดูอยู่**

**สมุดงานแยกคนละชุด + deployment แยก** คือทางเดียวที่พิสูจน์ได้ว่ามันเป็นไปไม่ได้

**② Demo ต้องส่ง LINE หรือแจ้งเตือนหาคนจริงไม่ได้เด็ดขาด**

ระบบเรามี "แจ้งเตือนฉุกเฉิน (อุบัติเหตุ) ที่ส่ง LINE เสมอ ไม่มีสวิตช์ปิด" — **ซึ่งถูกต้องสำหรับของจริง และเป็นหายนะใน Demo**
→ ชั้น `lineDeferFlush_` ต้องถูกตัดทิ้งทั้งก้อนในโหมด Demo ไม่ใช่ปิดด้วยค่าตั้งค่า

**③ 🔴 คนที่ยังไม่ใช่ลูกค้า จะล็อกอินยังไง**

เราล็อกอินด้วย **LINE อย่างเดียว** — คนที่กดจากโฆษณา Facebook ไม่มี LINE UID ในระบบเรา

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **ปุ่ม "เข้าดูเป็น แอดมิน/ครู/ผู้ปกครอง" ไม่ต้องล็อกอินเลย** | ลื่นที่สุด กดจากโฆษณาเข้ามาดูได้ทันที | ต้องมั่นใจ 100% ว่า deployment นั้นไม่มีข้อมูลจริง |
| ล็อกอินด้วยรหัสผ่านสาธิต | ยังคุมได้ว่าใครเข้า เก็บเป็น lead ได้ | มีแรงเสียดทาน คนกดออกตั้งแต่หน้าแรก |
| LINE ปกติ แล้วให้บทบาทสาธิต | ใช้โค้ดเดิมทั้งหมด | **ขอให้คนแปลกหน้าผูก LINE ก่อนดูสินค้า — ไม่มีใครทำ** |

**ผมแนะนำข้อแรก** และเป็นเหตุผลที่ข้อ ① ต้องเป็น deployment แยกจริงๆ ไม่ใช่ธง

### สิ่งที่ต้องมีในโหมดนี้
- 🔵 **แถบบนทุกหน้า** — "โหมดสาธิต · ข้อมูลทั้งหมดเป็นข้อมูลจำลอง"
- 🔄 **ปุ่มรีเซ็ตข้อมูลสาธิต** — ให้คนก่อนหน้าลองแก้อะไรไว้แล้วคนต่อไปยังเห็นหน้าจอที่สวยงาม
- 📘 **คู่มือการใช้งานในแอป** *(CoraClass มี — ของเราไม่มี)*
- 🧒 ข้อมูลจำลองที่ **"ดูเหมือนโรงเรียนจริง"** — มีเด็กขาดเรียน มีบิลค้าง มีใบลารออนุมัติ
  *(หน้าจอที่ทุกอย่างเรียบร้อยสมบูรณ์แบบ ไม่ได้แสดงว่าระบบแก้ปัญหาอะไรให้)*

## 📌 สิ่งที่ค้นพบระหว่างวิเคราะห์ CoraClass — ต้องบันทึกไว้สำหรับ Phase 4 (หลายโรงเรียน)

> **CoraClass จ่ายครูเป็น "รายชั่วโมง × อัตราค่าสอน" · เราจ่ายเป็น "เงินเดือน + OT"**

ระบบเงินเดือนของเรารองรับ**แบบเดียว** — โรงเรียนที่เราจะขายให้ อาจเป็นแบบใดแบบหนึ่ง **หรือทั้งสองแบบพร้อมกัน** (ครูประจำ + ครูพิเศษรายชั่วโมง)

**นี่ไม่ใช่ฟีเจอร์เสริม — มันคือเงื่อนไขว่าขายให้โรงเรียนประเภทไหนได้บ้าง** และควรตัดสินใจก่อนออกแบบ multi-tenant ไม่ใช่หลังจากนั้น
