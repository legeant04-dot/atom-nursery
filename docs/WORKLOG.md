## 2026-10-13 · Phase 2.4 (dual-write) + ชุดเอกสาร PDPA ให้ ผอ. ตรวจ

### 🔴 "dual-write" ที่ไม่ยิง Supabase ตอนเขียนชีต — และเหตุผลอยู่ใน repo นี้แล้ว

การอ่านตรงตัวคือ "ทุกครั้งที่เขียนชีต ให้ POST ไป Supabase ด้วย" · **ซึ่งรู้อยู่แล้วว่าผิดที่นี่**

> รายงานความเร็ว 06–09/10: **18:00 fail 13% · 19:00 15% · 20:00 37%**
> ชั่วโมงที่แย่ที่สุดของวัน และเป็นชั่วโมงที่คุณครูทุกคนลงเวลาออก
> สาเหตุ: **การยิง HTTPS 1 ครั้ง (LINE push) อยู่ใน write lock** — 300ms ที่ทั้งโรงเรียนเขียนอะไรไม่ได้

ยิง Supabase ทุกการเขียน = **ความผิดเดียวกัน แต่เกิดกับทุกการเขียน ไม่ใช่เฉพาะที่ต้องแจ้งเตือน**

จึงทำเป็น **การกระทบยอดนอกเส้นทางของ request**: ส่งออกชีตแบบที่ทำอยู่แล้ว → เทียบกับ Postgres →
**แก้เฉพาะแถวที่ต่างจริง** · **ไม่แตะโค้ดที่ใช้งานจริงแม้แต่บรรทัดเดียว**

### 🔴 รันซ้ำแล้วต้องไม่มีอะไรเปลี่ยน — นี่คือทั้งหมดของเฟสนี้

**ตัวซิงก์ที่รายงานว่า "ต่าง" ทุกครั้งที่รัน คือตัวเขียนที่ปลอมตัวเป็นตัวตรวจ**
และ Phase 2.5 (รายงานความต่างรายวัน) จะไม่มีอะไรให้รายงานเลย

กับดักที่เกือบโดน: `date` กลับมาจาก driver เป็น **Date object ที่ 17:00 UTC** ซึ่งคือเที่ยงคืนกรุงเทพ
เทียบด้วย UTC ตรงๆ แล้ว **ทุกแถวที่มีวันที่จะถูกเขียนทับทุกเย็น ตลอดไป** โดยไม่มีอะไร error
— ทดลองถอดการแปลงเขตเวลาออก **เทสต์ตก 12 ข้อ**

### เทียบส่วนต่าง ไม่ใช่โหลดใหม่

โหลดใหม่ทั้งก้อนทำงานได้ และใช้ไม่ได้: `id` ของทุกแถวเปลี่ยนทุกรอบ อะไรที่ชี้มาที่แถวด้วย id พังทุกคืน

และคีย์ถูกต่อด้วยตัวคั่นที่ไม่มีรหัสไหนมีได้ เพื่อให้ `('S-1','2026-10-13')` ชนกับ `('S-12','026-10-13')` ไม่ได้
— เรื่องแบบนี้ทำงานได้หลายปีแล้วอยู่ดีๆ ก็รวมบันทึกของเด็กสองคนเข้าด้วยกัน

### 🔴 บันทึกการตรวจสอบ เพิ่มได้อย่างเดียว

ถ้าเทียบส่วนต่างกับ audit log แล้วมีคนลบแถวออกจากชีต → จะกลายเป็น "ลบในฐานข้อมูลด้วย"

(เดือนของสลิป และการนับวันลา) · แก้ที่ `pg_lib.connect` ครั้งเดียว เพื่อให้ไม่มีเครื่องมือไหนลืมได้อีก

**⑥ `/^time/` ไป match `timestamptz`** — `SubmittedAt` ทุกใบถูกตรวจด้วยกติกาของ `HH:mm` แล้วกลายเป็น null

**⑦ ค่าที่ชีตเก็บได้ แต่คอลัมน์ที่มีชนิดรับไม่ได้** — เจอครบ 4 แบบในรอบกวาดเดียว
`"Sat Dec 30 1899"` ในช่องเวลา · `"500,000.00"` ในช่องตัวเลข · `"วันที่ 15"` · `"maybe"` ในช่อง boolean
**ทุกตัวอยู่ใน fixture อยู่แล้ว แปลว่าทุกตัวเคยเกิดขึ้นกับโรงเรียนนี้มาแล้ว**
และตัว migrate ครอบทั้งตารางไว้ใน 1 transaction → **ค่าเสียค่าเดียว = ทั้งตารางถูก rollback**

> กติกาใหม่: **แปลงค่าเฉพาะที่ความหมายชัดเจนจนไม่ต้องเดา ที่เหลือเก็บเป็น NULL แล้วบอก**

ดังนั้นทุกแถวยังถือเวลาเช็คอินของวันนี้ การ์ด "วันนี้ไม่มาเรียนตามที่ตกลงไว้" และป้ายเตือน DSPM ของวันนี้
— ทุกอย่างเป็นความจริงของคนละวัน และปุ่มเช็คอินจะเสนอให้กดย้อนหลังซึ่งเซิร์ฟเวอร์ปฏิเสธ
→ วันย้อนหลังเหลือแค่ **👁️ ดูบันทึก** กับ **⋯** เปลี่ยนสีพื้นหลัง และบอกเป็นคำว่าอ่านได้อย่างเดียว

**ไม่จำวันที่ข้ามการโหลด** — เปิดแอปตอนเช้าแล้วเจอวันอังคารที่แล้วโดยกดอะไรไม่ได้ แย่กว่าการกดเพิ่มอีกครั้ง

กล่องวันเกิดย้ายลงใต้รายชื่อเด็ก เพราะมันมี ◀ ▶ ของตัวเอง และลูกศรสองชุดซ้อนกันอ่านว่าเป็นอันเดียวกัน

### ตรวจสอบทั้งระบบ (v425)

- **🔴 เจอ handler ตาย 1 จุดใน 505** — `onclick="…toast(…)"` ในกล่อง Callback URL
  `onclick` ทำงานใน **global scope** แต่ `toast` อยู่ใน IIFE → ReferenceError ทุกครั้งที่แตะ
  (คัดลอกสำเร็จเพราะเป็นครึ่งซ้ายของ `&&` แล้วค่อย throw — ผู้ใช้ไม่เคยได้รับคำยืนยัน)
  แก้เป็น `window.COPY_` ซึ่งรองรับกรณี `navigator.clipboard` ไม่มี (nonsecure context) ด้วย
  → **`tools/test_inline_handlers.js`** ตรวจทั้งไฟล์ทุกครั้ง และมีการปลูก handler ปลอมเพื่อพิสูจน์ว่าตัวตรวจยังจับได้
- deployment จริงแข็งแรง: ping 20 ครั้ง **ok 20/20** p50 3.3s p95 8.5s
- เคยเจอ 404 / `ok:false` 3 ครั้งติดก่อนหน้านั้น แล้วหายเอง — **เป็นอาการของ Apps Script ไม่ใช่จากการ deploy**
  ตรงกับ `BAD_RESPONSE HTTP 404` ที่มีใน perf report อยู่แล้ว
- หน้าแรกคุณครู **13 คำสั่ง 1 คำขอ** และบันทึกตั้งค่า **9 คำสั่ง 1 คำขอ** — ยืนยันในเบราว์เซอร์จริง
- `Engine.gs` ตรงกับ `engine.js` · dist build ตรงกับ v425 · shadow routes ผ่าน 36/36
