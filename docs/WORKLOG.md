# บันทึกการทำงาน (Worklog)

บันทึกรายวันของสิ่งที่เปลี่ยนในระบบจริง — **เหตุผล** และ **หลักฐาน** ไม่ใช่แค่รายการฟีเจอร์
ประวัติแบบละเอียดอยู่ใน git log; ไฟล์นี้คือสิ่งที่ต้องอ่านก่อนจะตัดสินใจอะไรต่อ

## 2026-10-07 · v420 → v425 (GAS @338 → @343)

ทำตามคำขอของ ผอ. 7 ข้อ แบ่งเป็น 5 Phase · ชุดทดสอบ **151 → 156 suites** เขียวทั้งหมด

### 🔴 การวัดที่เปลี่ยนวิธีคิดของเราทั้งหมด

ยิงเข้า deployment จริง 14 ครั้ง สลับกันระหว่างคำขอที่ไม่ทำอะไรเลยกับคำขอที่อ่าน 11 ตาราง:

| | กลาง | ช่วง |
|---|---|---|
| คำขอที่ **ไม่ทำอะไรเลย** (`ping`) | 10.8s | 2.7 – 30.5s |
| คำขอที่ **อ่าน 11 collection** (`ping probe:2`) | 4.8s | 3.8 – 18.4s |
| เวลาอ่านตารางที่อยู่ข้างใน | **416ms** | 354 – 545ms |

**คำขอที่ทำงานมากกว่า กลับเร็วกว่าคำขอที่ไม่ทำอะไรเลย**

> **ขนาดของคำขอไม่ใช่ต้นทุน — การมีอยู่ของคำขอต่างหากคือต้นทุน**
> ต้นทุนของหน้าจอ ≈ (จำนวน round trip) × (3–30 วินาที) · งานของเราเล็กเกินกว่าจะมองเห็นในความแกว่งนั้น

ผลที่ตามมา (ทุกข้อเคยจ่ายราคามาแล้ว):
- collection ที่ cache อุ่นอ่านใน 12–130ms · ที่ **เย็นเสีย 5–6 วินาที** (`checkinStudent` 537KB เย็น = 6.6s / อุ่น = 61ms) — การเขียนทุกครั้งทำให้ cache เย็น
- การเปิด workbook **ฟรี** (`openFirst: 0ms`) — ที่เสียคือการ *อ่าน*
- **"แยก batch ใหญ่เพื่อให้ส่วนเร่งด่วนกลับมาก่อน" เป็นวิธีที่ผิดบนแพลตฟอร์มนี้** และเราทำมาแล้ว 2 รอบ (v373 แยก, v421 รวมกลับ)
- `await` ที่หลงอยู่ระหว่าง `api()` หลายตัว = แยก 1 คำขอเป็น 2 · **เป็นอักขระตัวเดียวที่แพงที่สุดในโค้ดเบสนี้** — มี test คุมไว้แล้วทั้ง `test_roundtrip_budget.js` และ `test_home_roundtrips.js`

เอกสารอ้างอิง: ดู `docs/PHASE_PLAN.md` §7 — เกณฑ์ **p50 < 1.5s** หลังย้ายไป Postgres จะเป็นไปได้ก็เพราะต้นทุนนี้หายไป ไม่ใช่เพราะโค้ดเราเร็วขึ้น

### Phase 1 — ของที่พัง (v420)

**🔴 เคสน้องโมน่า** — Admin แจ้งลาให้เด็กไม่ได้ ระบบตอบ "ไม่พบผู้ปกครอง"

ปุ่มส่งแจ้งลาเป็นปุ่มเดียวในหน้าผู้ปกครองที่ไม่ได้ส่ง `parentScope()` · ผู้ปกครองตัวจริงไม่เจอ
เพราะ `applyIdentity_` เติม `parentId` ให้จาก session — แต่ **payload ของ Admin ถูกส่งผ่านโดยไม่แตะ**
(ซึ่งเป็นสิ่งที่ทำให้ "ดูมุมมอง" ทำงานได้) จึงไม่มีใครเติมให้ · **กับดักเดียวกับ `staffAttendanceMonth` ใน v419**

ไล่ตรวจครบทั้ง 4 handler ที่เรียก `resolveParent_` — ไม่มีจุดอื่นที่ขาด

**ใบลาที่ Admin แจ้ง = ใบลาของโรงเรียน** (`FiledBy`) ตัดสินจาก **session** ไม่ใช่จาก payload
เพราะตอนดูมุมมอง ระบบส่ง `parentId` ของครอบครัวนั้นจริง ๆ ไม่มีอะไรอื่นแยกออกได้

**🔴 Error pop-up ค้าง เฉพาะตอนบันทึก** — `api.js` ติดป้ายชื่อ action และ "เขียนข้อมูลหรือไม่" ลงบน error
→ `err()` เลือกระหว่าง toast กับ dialog ที่ต้องกดปิด · แสดงรหัสข้อผิดพลาดด้วย เพราะ "ลองใหม่อีกครั้ง"
ไม่มีอะไรให้โรงเรียนรายงานกลับมา · **อ่านไม่ขึ้น dialog** — p50 7.3s, fail ~1/40 ส่วนใหญ่เป็นป้ายตัวเลข

### Phase 2 — ความเร็ว (v421)

| | ก่อน | หลัง |

เพื่อรายการประกาศที่ไม่มีใครรออยู่ · นี่คือส่วนหนึ่งของ "เช้านี้เข้าระบบแล้วค้าง"

**🔴 รายงานความเร็วตอบคำถามของตัวเองไม่ได้** — `staffCheckout fail=7 (32%)` โดยไม่มีรหัส

ความผิดพลาดจริง** (`failCodes` vs `codes`) — `ALREADY_CHECKED_OUT` คือระบบทำงานถูก ต้องไม่ไปอยู่ในรายการที่ต้องแก้

> ⚠️ **ยังค้าง:** สาเหตุของ `staffCheckout` 32% · ต้องรอรายงานรอบหน้า

### Phase 3 — ค้นหา & สรุปรายปี (v422)

**ค้นหาครอบครัวจากชื่อเด็ก และกลับกัน** — สร้างจาก `parentKidsMap` ไม่ใช่จากข้อมูลนักเรียน
เพราะเด็กผูกกับครอบครัวได้ **3 ทาง** (`USER_LINKS` / `STUDENTS.ParentID` / `PARENTS.StudentID` ของเดิม)
และมีแค่ map นั้นที่รู้ครบทั้งสาม · ใช้ helper ตัวเดียวทั้ง 2 ช่องค้นหา · ไม่เสีย round trip เพิ่ม

**สรุปรายปีเฉพาะคุณครู** — `reviewStaff` แยกจาก `payableStaff` โดยเจตนา:
`payableStaff` เก็บ ผอ. ไว้เพราะเป็น Admin ที่รับเงินเดือน (มติ 2026-09-29) การใช้ตัวกรองเดียวกัน
จะทำให้**สลิปของ ผอ. หายจากหน้าเงินเดือน**

**🔴 นับวันทำงานจากวันเริ่มงานรายคน** — บั๊กเดียวกับ 125 วันของ v419 แต่ลึกลงไปอีกชั้น:
v419 แก้ว่า*โรงเรียน*เริ่มเมื่อไหร่ แล้วทุกคนยังถูกวัดด้วยปฏิทินทั้งปีอยู่ดี
ใช้กฎ `owesDay_` ตัวเดียวร่วมกับหน้ารายเดือน · เงื่อนไขสองชั้นซ้อนกัน วันไหนช้ากว่าชนะ

### Phase 4 — บันทึกนักเรียน (v423)

ปฏิทิน วัน/เดือน/ปี บนหัวจอชั้นเรียน (`<input type="date">` จำกัดไม่เกินวันนี้)

**🔴 ความเสี่ยงไม่ได้อยู่ที่ตัวปฏิทิน** — `classList` ตอบเป็น "วันนี้" เสมอไม่ว่าจะขอบันทึกของวันไหน
ดังนั้นทุกแถวยังถือเวลาเช็คอินของวันนี้ การ์ด "วันนี้ไม่มาเรียนตามที่ตกลงไว้" และป้ายเตือน DSPM ของวันนี้
— ทุกอย่างเป็นความจริงของคนละวัน และปุ่มเช็คอินจะเสนอให้กดย้อนหลังซึ่งเซิร์ฟเวอร์ปฏิเสธ
→ วันย้อนหลังเหลือแค่ **👁️ ดูบันทึก** กับ **⋯** เปลี่ยนสีพื้นหลัง และบอกเป็นคำว่าอ่านได้อย่างเดียว

**ไม่จำวันที่ข้ามการโหลด** — เปิดแอปตอนเช้าแล้วเจอวันอังคารที่แล้วโดยกดอะไรไม่ได้ แย่กว่าการกดเพิ่มอีกครั้ง

กล่องวันเกิดย้ายลงใต้รายชื่อเด็ก เพราะมันมี ◀ ▶ ของตัวเอง และลูกศรสองชุดซ้อนกันอ่านว่าเป็นอันเดียวกัน

**🔴 ของจริงอยู่ที่ปุ่มบันทึก** — เดิมยิง **9 รอบเรียงทีละรอบ** (`setSchoolConfig` + `setConfigVal`×5

**🔴 โค้ดเดิมอ่าน `#cfgLat` โดยไม่เช็คว่ามีช่องนั้น** — ถ้าแยกหน้าโดยไม่แก้ จะพังทันทีที่เปิด
"ตั้งค่าวันลา" แล้วกดบันทึก · ใช้ฟังก์ชันบันทึกตัวเดียวทั้ง 5 หน้า ทุกช่องเป็น optional

เดิม**ไม่มีการดักข้อผิดพลาดเลย** — บันทึกไม่สำเร็จแล้วหน้าต่างค้างเงียบ ๆ ซึ่งหน้าตาเหมือนสำเร็จ

### ตรวจสอบทั้งระบบ (v425)

- **🔴 เจอ handler ตาย 1 จุดใน 505** — `onclick="…toast(…)"` ในกล่อง Callback URL
  `onclick` ทำงานใน **global scope** แต่ `toast` อยู่ใน IIFE → ReferenceError ทุกครั้งที่แตะ
  (คัดลอกสำเร็จเพราะเป็นครึ่งซ้ายของ `&&` แล้วค่อย throw — ผู้ใช้ไม่เคยได้รับคำยืนยัน)
  แก้เป็น `window.COPY_` ซึ่งรองรับกรณี `navigator.clipboard` ไม่มี (nonsecure context) ด้วย
  → **`tools/test_inline_handlers.js`** ตรวจทั้งไฟล์ทุกครั้ง และมีการปลูก handler ปลอมเพื่อพิสูจน์ว่าตัวตรวจยังจับได้
- deployment จริงแข็งแรง: ping 20 ครั้ง **ok 20/20** p50 3.3s p95 8.5s
- เคยเจอ 404 / `ok:false` 3 ครั้งติดก่อนหน้านั้น แล้วหายเอง — **เป็นอาการของ Apps Script ไม่ใช่จากการ deploy**
  ตรงกับ `BAD_RESPONSE HTTP 404` ที่มีใน perf report อยู่แล้ว
- หน้าแรกคุณครู **13 คำสั่ง 1 คำขอ** และบันทึกตั้งค่า **9 คำสั่ง 1 คำขอ** — ยืนยันในเบราว์เซอร์จริง
- `Engine.gs` ตรงกับ `engine.js` · dist build ตรงกับ v425 · shadow routes ผ่าน 36/36
