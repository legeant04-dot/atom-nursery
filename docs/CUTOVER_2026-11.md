## 🔴 ทำไม Supabase ไม่อยู่ในรอบนี้

Phase 2 พิสูจน์ **ชั้นข้อมูล** เสร็จแล้วจริง — `pg_engine.js` ป้อนเอนจินจาก Postgres ได้
และ **101 ชุดทดสอบรันบน Postgres จริง** ผ่านแล้ว นั่นคือของจริงและเป็นงานที่ทำไปแล้ว

แต่สิ่งที่ยังไม่มีคือ **ที่ให้มันรัน**:

| | สถานะ |
|---|---|
| เอนจิน (`Engine.gs` 7,524 บรรทัด) | ✅ พิสูจน์แล้วว่ารันบน Postgres ได้ |
| **ของที่เหลือใน `src/` 14,308 บรรทัด** | ❌ ยังไม่ได้ย้าย |
| ล็อกอิน LINE LIFF + HMAC session (`Auth.gs` 883 บรรทัด) | ❌ |
| แจ้งเตือน LINE (`Notify.gs` 552 บรรทัด) | ❌ |
| งานตามเวลา — เตือน 06:50 · digest 10:00/20:00 · backup | ❌ |
| ไฟล์ใน Drive — สลิป รูปนักเรียน รูปบันทึก รูปอุบัติเหตุ *(13 จุดเรียก DriveApp)* | ❌ และต้องย้ายของเก่าด้วย |
| SlipOK | ❌ |
| **Edge Function / เซิร์ฟเวอร์ที่เบราว์เซอร์เรียกได้** | ❌ **ยังไม่มีเลย** — `webapp/api.js` ยังชี้ `script.google.com` |

เทียบกัน: รอบนี้ย้าย **ชื่อที่ผู้ใช้พิมพ์** · Supabase คือย้าย **ที่เก็บเงิน ที่เก็บรูปเด็ก และประตูล็อกอิน**
พร้อมกันทั้งหมด ในระบบที่โรงเรียนใช้จริงทุกเช้า

> และกฎในเอกสารของเราเองเขียนไว้แล้วว่า:
> **ย้ายสองอย่างพร้อมกันแล้วพัง จะไม่รู้ว่าพังเพราะอะไร**

**ข้อดีของการย้ายโดเมนก่อน:** พอโดเมนเป็นของโรงเรียนแล้ว วันที่ย้ายไป Supabase จริง
**ผู้ปกครองจะไม่รู้สึกอะไรเลยแม้แต่น้อย** เพราะที่อยู่ไม่เปลี่ยนอีกต่อไป
นั่นคือเหตุผลทั้งหมดที่การมีโดเมนของตัวเองคุ้ม และเป็นเหตุผลที่ควรทำก่อน
