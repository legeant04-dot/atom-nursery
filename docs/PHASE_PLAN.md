**🔴 ข้อควรรู้ 3 ข้อที่ได้จากการทดลอง ไม่ใช่จากการอ่านเอกสาร:**

1. **การเชื่อมต่อที่ผมใช้อยู่ (`postgres`) ข้าม RLS ทั้งหมด** — `rolbypassrls = true` และไม่มีตารางไหนตั้ง
   `force row level security` · เป็นเรื่องปกติของ Supabase และจำเป็นสำหรับการ migrate
   **แต่แปลว่าเทสต์ที่เขียนแบบตรงไปตรงมาจะพิสูจน์อะไรไม่ได้เลย** — ต้อง `set local role authenticated` ก่อนเสมอ
   และ **`service_role` key ห้ามออกจากเซิร์ฟเวอร์เด็ดขาด**
2. **RLS เปิดแต่ไม่มีนโยบาย = ปฏิเสธทุกอย่าง** (fail closed) — ลองถอดนโยบายออกแล้วได้ 0 แถว ไม่ใช่ 3
   ความผิดพลาดที่อันตรายจริงคือนโยบายที่**หลวมเกินไป** ซึ่งทดลองแล้วเช่นกัน: เปลี่ยนเป็น `using(true)` → เทสต์ตก 11 ข้อ
3. **ข้อ 6 ของเทสต์อ่าน "ข้อความ" ของนโยบายทั้ง 52 ข้อ** — จับ `using(true)` ได้แม้ในตารางที่ไม่มีข้อมูลทดสอบ
   (ยืนยันแล้วกับ `payroll`) · §1–§4 ทดสอบจริงแค่ 2 ตาราง และ "ตารางเดียวที่หลวม" คือวิธีที่ข้อมูลรั่วทั้งที่ทุกอย่างดูเขียว

**และพบ 1 เรื่องที่ต้องตัดสินใจใน Phase 2:** `AUDIT_LOG` มีอยู่ทั้ง 2 workbook ชื่อชนกันเป็นตารางเดียว
`create table if not exists` ทำให้ตัวที่ 2 ถูกข้ามแบบเงียบๆ · **ตรวจแล้วว่าคอลัมน์เหมือนกันทุกตัว จึงไม่มีอะไรหาย**
แต่ตอนเขียน migration ต้องตั้งใจว่า **รวมเป็นตารางเดียว** และระวัง `record_id` ซ้ำข้าม workbook

> **Phase 1 ไม่มีข้อมูลนักเรียนจริงแม้แต่แถวเดียว** — ใช้ข้อมูลจำลองที่มีอยู่แล้ว จนกว่า 1.5 จะเสร็จและ ผอ. เซ็น
