## 🔴 ปัญหาที่แผนนี้แก้ (พบในระบบวันนี้)

การลงทะเบียนเด็กใหม่ในแอปตอนนี้ (`addChildNew` · `registerNew` ใน webapp/engine.js) **สร้างนักเรียนสถานะ ACTIVE ทันที
และตั้ง EnrollDate = วันที่กรอก** · คนที่แค่ "สนใจ" จึงกลายเป็นนักเรียน ปรากฏในรายชื่อชั้น ในการเช็คชื่อ และในระบบบิล
ตั้งแต่วินาทีที่กด "บันทึก" — ก่อนโรงเรียนจะตัดสินใจรับ

**หลักของแผน: ใบสมัคร ≠ นักเรียน** · ใบสมัครอยู่ในคิวของตัวเอง ไม่แตะรายชื่อนักเรียน การเช็คชื่อ หรือเงินเลย
จนกว่าแอดมินจะกด "รับเข้า" และเลือก **วันเริ่มเรียนจริง** (วันในอนาคต = "ยังไม่เริ่มเรียน" ซึ่งระบบรองรับอยู่แล้ว → ไม่ถูกเก็บเงินก่อนวันนั้น)

## เส้นทาง

```
หน้าแรก [📝 สมัครเรียน] → เข้าด้วย LINE
  → ผู้ปกครองใหม่: ลงทะเบียนผู้ปกครอง (หน้าเดิม registerParent — มีรูปยืนยันตัวตนสำหรับการเข้าระบบ)
  → แบบฟอร์มใบสมัคร 7 ขั้น (ข้อมูลผู้ปกครองกรอกไว้แล้วให้อัตโนมัติ) → ตรวจทาน → ยืนยัน + ลงชื่อ → ส่ง
  → (ถ้าต้องการ) แนบเอกสาร — ตอนนี้ หรือภายหลังจากหน้า "ใบสมัครของฉัน"
  → 🔔 แอดมิน: "ใบสมัครใหม่"
แอดมิน: ดูใบสมัคร · นัดเยี่ยมชม · ถ่าย/อัปโหลดเอกสารแทน · [✅ รับเข้า] หรือ [❌ ไม่รับ]
  → รับเข้า: เลือกชั้น (ค่าเริ่มตามอายุ) · วันเริ่มเรียน · แผนค่าเรียน
     → ระบบสร้างนักเรียน + ผูกกับผู้ปกครอง/LINE + ผู้รับแทน + น้ำหนักส่วนสูงแรก + ความยินยอม PDPA
     → ไปหน้าออกบิล (ค่าแรกเข้า/มัดจำ — ระบบบิลเดิม ไม่เขียนโค้ดเงินใหม่)
  → 🔔 ผู้ปกครอง: "ใบสมัครได้รับการตอบรับ" · LINE ตามสวิตช์หัวข้อใหม่ (ค่าเริ่ม: แจ้งในแอปอย่างเดียว — โควตา LINE)
```

## หน้าจอผู้ปกครอง (Mobile First)

- **หนึ่งหัวข้อต่อหนึ่งหน้า** ตามใบสมัครกระดาษ: 1 ข้อมูลเด็ก · 2 ผู้ปกครอง · 3 ผู้รับแทน · 4 สุขภาพ · 5 เอกสาร · 6 คำรับรอง · 7 PDPA
- แถบความคืบหน้า "ขั้น 2/7" · ปุ่ม "ถัดไป" ติดล่างจอ (savedock) · ตรวจช่องที่จำเป็นทีละขั้น ไม่ใช่ตอนท้าย
- ตัวเลือกเป็นปุ่มแตะใหญ่ (ด.ช./ด.ญ. · กรุ๊ปเลือด · เคย/บางครั้ง/ไม่เคย) แทนช่อง ☐ เล็ก ๆ
- **บันทึกร่างในเครื่องอัตโนมัติ** ทุกช่อง — ปิดแอปแล้วกลับมาทำต่อได้ (ไม่ส่งอะไรขึ้นเซิร์ฟเวอร์จนกด "ส่ง")
- หน้า **ตรวจทาน** ก่อนส่ง แตะหัวข้อเพื่อกลับไปแก้
- ไทย/อังกฤษ ตามภาษาของแอป — ข้อความชุดเดียวกับใบสมัครกระดาษที่ทำไว้ (TH/EN)
- เอกสาร: ถ่ายด้วยกล้องหรือเลือกไฟล์ (รูป/PDF) · ย่อรูปก่อนส่ง · แต่ละรายการมีสถานะ ✅ แนบแล้ว / ⬜ ยังไม่แนบ / 🏫 นำมาวันเยี่ยมชม

## การยืนยันและ "ลายเซ็น" (คำตอบข้อ 3)

ผู้ปกครองติ๊กยืนยัน + พิมพ์ชื่อ-นามสกุล (บังคับ) · เซ็นด้วยนิ้วบนจอ (ไม่บังคับ) · ระบบบันทึก:
เวลาของเซิร์ฟเวอร์ · บัญชี LINE ที่ยืนยัน · ชื่อที่พิมพ์ · **ฉบับของข้อความที่ยินยอม** (รหัสของข้อความ PDPA ตอนนั้น —
ถ้าวันหน้าข้อความเปลี่ยน ยังรู้ว่าผู้ปกครองคนนี้ยินยอมกับข้อความไหน) · ความยินยอม 4 ข้อของ 7.3 แยกเป็นรายข้อ

## "รับเข้า" สร้างนักเรียนแบบเดียวกับทุกทาง

ใช้ทางเดียวกับ `addStudentByAdmin` / `addChildNew` ในเอนจิน (กันซ้ำเดิม · ชั้นตามอายุ · โฟลเดอร์ Drive · น้ำหนักส่วนสูงแรก)
**ไม่เขียนทางสร้างนักเรียนทางที่สี่** — สองทางที่สร้างนักเรียนต่างกันคือบั๊กที่รอคนอ่าน (หมายเหตุใน engine.js)
ต่างกันอย่างเดียว: EnrollDate = วันเริ่มเรียนที่แอดมินเลือก ไม่ใช่วันนี้

## สิ่งที่ต้องไม่กระทบ

- ผู้ปกครองเดิม: "เคยลงทะเบียนแล้ว" (claimParent) · เชื่อมเด็กด้วยเลขบัตร (linkExisting) — **ไม่เปลี่ยน**
- แอดมินเพิ่มนักเรียนเอง (addStudentByAdmin) — **ไม่เปลี่ยน** (สำหรับครอบครัวที่ยื่นกระดาษ)
- บิล การเช็คชื่อ รายชื่อชั้น — ใบสมัครไม่ปรากฏที่ใดเลยจนกว่าจะรับเข้า (มีชุดทดสอบยืนยัน)
- ปุ่มลงทะเบียนเด็กแบบเดิม ถูกแทนด้วยใบสมัคร **ในวันเดียวกับที่ปุ่ม "รับเข้า" ใช้งานได้** — ไม่มีช่วงที่ครอบครัวใหม่เพิ่มลูกไม่ได้

## ลำดับงาน (ปรับจากที่เสนอครั้งแรก)

ครั้งแรกเสนอ "ระยะ 1 = ฟอร์ม + คิว" — แต่ถ้ายังไม่มีปุ่มรับเข้า ใบสมัครจะค้างในคิวโดยทำอะไรต่อไม่ได้
และจะเปลี่ยนเส้นทางเดิมไม่ได้ จึงย้าย "รับเข้า" มาไว้ระยะ 1:

| ระยะ | งาน | ใช้ได้จริงเมื่อจบระยะ |
|---|---|---|
| **1** | ฟอร์ม 7 ขั้น (TH/EN) · ยืนยัน+log · คิวใบสมัครของแอดมิน · นัดเยี่ยม · รับเข้า/ไม่รับ · 🔔 สองฝั่ง · แทนปุ่มลงทะเบียนเด็กเดิม | ครอบครัวใหม่สมัครได้ แอดมินรับเข้าแล้วออกบิลได้ |
| **2** | เอกสารแนบ (ผู้ปกครอง + แอดมินอัปโหลดแทน) · ช่องตรวจเอกสารครบ/ค้าง · ลบเอกสารของใบที่ไม่รับตามกำหนด | เก็บเอกสารในระบบ ไม่ต้องใช้กระดาษ |
| **3** | ความยินยอมข้อ 7.3 คุมการแสดงรูปจริง (ไม่ยินยอม = ไม่แสดงรูปเด็กในบันทึก/ประชาสัมพันธ์) · พิมพ์ใบสมัครที่กรอกแล้วเป็นแบบฟอร์มเดิม | ปิดช่องที่ยังไม่มีสวิตช์ "ไม่ให้ใช้รูป" รายคน |

แต่ละระยะ: ทดสอบในเครื่อง → `test_all` → ให้ ผอ. ลองบนมือถือ → deploy เมื่อสั่ง
